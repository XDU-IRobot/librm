# 简介

librm 是一个面向 Robomaster 机器人电控开发的嵌入式软件框架。它最大的价值概括位四个字就是：省事好用。

一台性能优异的机器人离不开大量花在尝试控制方案、调试算法、优化参数上的时间，但在此之前，开发者往往要花费大量时间在与控制逻辑无关的工作上：查手册、配外设、处理协议、移植驱动、写离线检测、等等。

librm 把全部这些脏活用成体系且标准化的方式做好，提供稳定易用的底层能力，让开发者可以专注于算法和控制逻辑本身。librm 不能直接把一个队伍送到国赛八强，但坚实的基础让一个队伍有更多时间去做真正有价值的事情。

本项目由西安电子科技大学 IRobot 战队在 2024 赛季启动开发，现以 MIT 协议开源。欢迎各参赛队和机器人开发者使用，如果有任何问题或建议，欢迎提交 issue 或 pull request。

## 你可以用 librm 做什么

### 把外设初始化那些坑替你踩完

以 CAN 为例。STM32 HAL 的 `CAN_InitTypeDef` 有十来个字段，位时序、SJW、FIFO 锁定、自动重传各有各的语义；过滤器要按寄存器格式算 ID 和 mask；收发的 mailbox 数量、BUS-OFF 恢复、回调注册又各有讲究。这些配置单看文档都能配，但配错一项的现象往往只是"不通信"或"偶尔丢帧"，排查一次就够喝一壶。

而机器人上一条 CAN 总线，绝大多数时候的需求就是一个波特率加上收发。librm 按这个假设封装了一层：

```cpp
rm::hal::Can can(&hcan1);
can.Begin();                                    // 注册回调、启动外设、使能中断

rm::hal::CanFrame frame{};
frame.std_id = 0x200;
frame.dlc = rm::hal::CanFrame::kDlc8;
can.Write(frame);                               // 等待 mailbox / 处理 BUS-OFF 交给封装
```

CubeMX 里选好外设和波特率，剩下的调用顺序和 corner case 由 librm 处理。需要更细的控制时，HAL 句柄还在你手里。

串口、GPIO、定时器同样遵循上述思想，提供相应的简易HAL封装。

接进已有工程只需要在 CMakeLists 里加几行：

```cmake
add_subdirectory(librm)
target_link_libraries(${PROJECT_NAME} PRIVATE rm)
```

不需要额外的构建系统，没有各种闹不清的配套工具。

### 模块组合能力

librm 的模块不是孤立的功能点，它们被设计为可以自由组合：

```cpp
// 组合示例：限功率底盘控制。将裁判系统、功率模型、PID、底盘运动学、CAN限流组合在一起
rm::hal::ThrottledCan<128> can(1000, &hcan1);       // 定频 1kHz 发送，防止总线拥塞
rm::device::Referee<rm::device::RefereeRevision::kV170> ref;
rm::modules::MotorPowerModel power_model(rm::modules::MotorPowerModel::kM3508);
rm::modules::MecanumChassis chassis(0.3f, 0.4f);

auto power_limit = ref.data().robot_status.chassis_power_limit;  // 裁判系统 -> 功率上限
auto [lf, rf, lr, rr] = chassis.Forward(vx, vy, w);              // 运动学 -> 四轮目标转速
power_model.DistributePower<4>(states, currents, power_limit, output); // 功率模型 -> 限幅
```

这些模块之间的衔接是自然发生的。因为它们共享同一套类型定义、同一个CAN抽象、同一种错误处理方式。你不需要为每个组合写胶水代码。

### 跨平台能力

外设接口统一之后，librm 顺带获得了跨平台能力。同一份上层代码可以同时编译到 STM32 和 Linux 上：

```cpp
// 这段代码在 STM32、Linux PC、树莓派上完全一致
rm::hal::Can can(&hcan1);                          // STM32: HAL CAN；Linux: SocketCAN
rm::device::M3508 motor(can, 1);                    // M3508 电机，ID=1
rm::modules::PID pid(10, 0.5, 0, 16384, 5000);     // 速度环 PID

can.Begin();
while (true) {
    pid.Update(target_rpm, motor.rpm());            // 速度闭环
    motor.SetCurrent(pid.out());                    // 电流输出
    rm::device::DjiMotorBase::SendCommand();        // 统一发送 CAN 帧
    rm::core::SleepMs(1);
}
```

不管是[STM32上的CubeMX工程](../integration/stm32_cubemx.mdx)还是[Linux板子](../integration/linux_cmake.mdx)，配置好CMake后上面的例程就可以让一个3508电机转起来。

好处是可以利用电脑灵活的调试能力去写电机驱动、测试算法，调好之后直接搬到 STM32 上跑。
